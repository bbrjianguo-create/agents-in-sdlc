最初は、プロジェクトに小さな機能を追加しました。しかし、より大きな変更には、より確実なプロセスが必要です。GitHub Copilot CLI は、組織の既存のフローに沿って動作するよう作られており、適切なものを適切な方法で構築できます。このレッスンは、一般的なエージェント駆動の開発プロセスを段階的に体験する複数のレッスンの最初です。Issue から新機能を生成し、コードが有効であること、機能が期待どおりに動作することを確認し、最終的にプロジェクトへ問題なくマージします。

> [!NOTE]
> 機能のワークフローが続く間は、同じ会話とブランチを使用します。通常は、扱うファイルの種類ごとにブランチや PR を分けますが、ここでは中心となる概念に集中できるよう、手順を簡略化しています。

このレッスンでは、次の内容を学習します。

- GitHub Issue から新しい Copilot の会話を開始する。
- Plan モードで要件を定義する。
- Autopilot モードで新機能を実装する。
- コードをレビューする。
- 転送されたブラウザーで機能を手動で検証する。

この機能の作業を続ける中で、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加し、QA エージェントを作成して、機能の PR を作成します。

## シナリオ

Tailspin Toys のカタログは拡大しており、訪問者はカテゴリーとパブリッシャーでゲームを絞り込む必要があります。バックログの Issue にはこの機能が記載されていますが、カテゴリーの組み合わせ方といった詳細は、コーディングの前に合意しておく必要があります。Plan モードでそれらを決定し、その後 Autopilot で範囲を限定した実装を許可します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、基本がいっそう重要になります。多くの開発者は、次のようなフローで作業します。

1. 作業内容が記載された、登録済みの Issue から始める。
2. 構築する内容の計画を作成する。
3. コードを作成してレビューする。
4. テストを実行してコードを検証する。
5. 新しい機能を手動で検証する。
6. pull request (PR) を作成する。
7. コードのレビューと継続的インテグレーションが成功したら、コードをマージする。

> [!NOTE]
> チームや組織によって細部は異なりますが、ほとんどは上記の流れのバリエーションです。

この標準的な方法を守ることで、AI が生成したコードが要件を満たし、手書きのコードと同じ審査プロセスを通過することを保証できます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: あなたとエージェントが協力して作業します。エージェントは変更を提案し、あなたの入力を待ってから先に進みます。
- **Plan**: エージェントが最初に計画を作成します。プロジェクトファイルの編集はブロックされます。
- **Autopilot**: エージェントが自律的に作業します。タスクが完了するまで、コードの作成、テストの実行、改善を繰り返します。

まず Plan モードで始め、計画をレビューしてから、Autopilot で実装します。

## Issue から始める

フィルター機能の作業を始める前に、Codespace に戻り、リポジトリとターミナルの準備を整えます。

1. Codespace に戻ります。停止している場合は、再起動してから進めます。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルター機能の作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して、**Issues** タブを開きます。
7. <kbd>A</kbd> を押して、すべての Issue を表示します。
8. 方向キーで、**Allow users to filter games by category and publisher** というタイトルの Issue を選択します。
9. <kbd>C</kbd> を押して、Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または近い番号) で始まっていることを確認してください。`#` を使うと、GitHub の Issue や pull request (PR) をコンテキストに含められます。

## フィルター機能を計画する

計画を立てると、機能の実装やタスクの実行を Copilot に任せる前に、取るべき方法を定義できます。複雑な作業では、少し時間をかけて計画することをお勧めします。Plan モードに切り替えて、計画の作成を Copilot に依頼します。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下のモードインジケーターに **Plan** と表示されていることを確認します。
2. 前の手順で追加した Issue 参照の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot が計画の作成に取りかかります。まずプロジェクトを調査し、次に最適な方法を判断します。

3. 途中で、フィルター機能の動作について Copilot から質問されることがあります。好みに合わせて回答してください。正解や不正解はありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 上下にスクロールして、計画をレビューします。
6. 決定した内容に合わない部分があれば、計画の修正を Copilot に依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、実装に進みます。Autopilot を使って、Copilot に任せましょう。

Autopilot では、Copilot は完了したと判断するまで、課題に対して反復的に取り組みます。

1. **Accept plan and build on autopilot (recommended)**、またはお使いのバージョンで同様のラベルが付いたオプションを選択します。
2. プロンプトの下のモードインジケーターに **Autopilot** と表示されていることを確認します。
3. Copilot が作成済みの計画に沿って作業を進め、コードを生成し、テストを実行する様子を確認します。

> [!NOTE]
> 承認すると、実装がすぐに始まる場合があります。そのため、事前に計画をレビューしてください。Copilot が依存関係の不足やポートの競合を報告した場合は、セットアップの問題を解決するまで、チェックが完了したと見なさないでください。

## 実装をレビューして検証する

コードが生成されたら、他のコードと同様に、マージ前にレビューする必要があります。コードをレビューし、サイトを実行して、すべて問題がないことを確認します。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モードインジケーターに **Plan** や **Autopilot** が表示されていないことを確認します。
2. `/diff` を入力し、フィルター機能の実装とテストを確認します。
3. 結果を、Issue と計画時に決定した内容と比較します。
4. コードのレビューが終わったら、<kbd>Esc</kbd> を押して差分ビューを閉じます。
5. プロジェクトのチェックの出力を確認し、失敗があれば解決を Copilot に依頼します。

## 新機能を確認する

コードに問題はなさそうですが、実際に動作するでしょうか。先ほどと同じようにアプリを起動し、Codespaces の転送ポート経由でサイトを開きます。

1. アプリを起動するよう Copilot に依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces からポート `4321` が利用可能になったと通知されたら、**Open in Browser** を選択します。
3. カテゴリーでの絞り込み、パブリッシャーでの絞り込み、計画で合意した組み合わせを試します。
4. リセットと結果が空の場合の動作が、Issue とあなたの決定内容に一致することを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。

## まとめと次のステップ

会話モードを使い分けて、機能を構築しレビューしました。このレッスンでは、次の作業を行いました。

- GitHub Issue から新しい Copilot の会話を開始した。
- Plan モードで要件を定義した。
- Autopilot モードで新機能を実装した。
- コードをレビューした。
- 転送されたブラウザーで機能を手動で検証した。

次は、[カスタム指示を使って][next-lesson]、コードの生成方法をさらに掘り下げ、文書化されたプラクティスに従っていることを確認します。

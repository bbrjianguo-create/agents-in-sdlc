GitHub Copilot をエージェントモードにすると、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。その作業はお使いのマシン上でリアルタイムに行われるため、VS Code の Copilot Chat では、すべてのツール呼び出しとファイルの編集が行われるたびに、その実行状況を確認できます。各差分をインラインでレビューし、個々の変更を承認または却下できます。また、エディターを離れずに、フォローアップのプロンプトで会話を調整して、作業を改善または拡張できます。

この演習では、次の内容を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッションの途中でエージェントを調整し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson] で使用したアクセシビリティのカスタムエージェントが、ハイコントラストモードを実装しています。作業の進行中に、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも用意したいとのことです。新しい会話を最初から始めるのではなく、既存のセッションを調整して、作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各ステップ (調査するファイル、実行するコマンド、提案する編集) が表示されます。各ファイルの編集は、差分と **Keep** / **Undo** のコントロールとともに、チャット内にインラインで表示されます。

1. 演習 4 の Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして、各ツール呼び出しが反映される様子を確認します。ファイルの読み取り、ファイルの編集、実行を求められるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - **Keep** を選択すると、変更を承認します。
    - **Undo** を選択すると、変更を元に戻し、エージェントにやり直させます。
4. チャットの上部にある **Files changed** インジケーターを開くと、このセッションでエージェントが変更した作業セット全体を確認することもできます。

> [!NOTE]
> ツール呼び出しで許可を求められた場合 (たとえば、ターミナルコマンドの実行)、エージェントは一時停止して **Allow** プロンプトを表示します。問題ないと判断したコマンドのみを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。行った変更を要約する最終メッセージが表示されます。

## エージェントを調整してライトモードを追加する

ハイコントラストモードができたので、同じ会話を拡張して、ライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントは、変更したコンポーネント、使用したスタイリングの方法、設定したローカルストレージのパターンなど、以前の作業のすべてのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは、中断したところから再開し、すでに行った変更を調べて、ライトモード向けの追加を提案します。
3. ハイコントラストのときと同じように、新しい編集が反映されるたびにレビューします。各差分で **Keep** または **Undo** を使用します。
4. エージェントが意図しない方向に進んだ場合 (たとえば、好ましくない方法で切り替えの UI をリファクタリングしようとした場合)、チャットの入力欄の横にある **Stop** ボタンで停止し、補足するフォローアップのメッセージを送信できます。

> [!TIP]
> 進行中のセッションを調整するほうが、やり直すよりも速くできます。フォローアップのプロンプトを使って、調整を依頼したり (「CSS を簡素化してください。セレクターを重複させず、CSS 変数を使用してください」)、軌道を修正したり (「3 つ目の切り替えは追加しないでください。ライトモードを既存の設定パネルに統合してください」)、範囲を拡張したり (「両方の切り替えにキーボードショートカットも追加してください」) できます。

## 作業セットをレビューする

作業をコミットする前に、エージェントが変更したすべてのものをざっと確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連するテストの更新が含まれているはずです。
3. 変更されたファイルをいくつか開いて、差分を確認します。カスタムエージェントのアクセシビリティのパターン (ARIA 属性、キーボードナビゲーション、セマンティック HTML、ローカルストレージによる永続化) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。[次のレッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視して調整しました。各ファイルの編集が反映されるたびにレビューし、変更を承認または却下し、フォローアップのプロンプトでコンテキストを失わずに作業を拡張しました。

このレッスンでは、次の内容を確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイルの編集を承認または却下する。
- フォローアップのプロンプトで、セッションの途中でエージェントを調整する。

[次のレッスン][next-lesson]では、アクセシビリティの作業を pull request として公開し、このラボを通じてローカルのカスタムエージェントが生成した変更をレビューします。
